How to Edit Content

All the content of your portfolio lives inside one file: index.html. To edit it, open it with a text editor. The best free option is Notepad++ (Windows) or Visual Studio Code. Do not use Microsoft Word — it will corrupt the file.

The golden rule for finding things: use Ctrl + F to search for the exact text you see on the website. Find it in the file, change just that text, and save.

Before editing

Always make a backup copy of index.html before editing. Right-click the file → Copy → Paste in the same folder. Rename it index-backup.html. If anything breaks, you can restore from this copy.

How to Update Your Resume

The Resume button on the hero links to a PDF file stored alongside index.html. Swapping it is simple:

1

Export your updated resume as a PDF

Name it exactly Edwin_Gyasi_Resume.pdf — same name as the current file. Underscores, capitalisation, and the .pdf extension must match exactly.

2

Replace the old PDF

Copy the new PDF into the Engineering Site folder. Windows will ask if you want to replace the existing file — click Replace.

3

Deploy to GitHub

Open your terminal in the project folder and run the three deploy commands from Section 06. The live site will serve the new PDF within a minute.

If you rename the PDF

If you choose a different filename, you must also update index.html. Search for Edwin_Gyasi_Resume.pdf in the file and change it to match your new filename exactly.

How to Change Colors and Fonts

All colors and fonts are controlled from one place at the very top of the <style> section in index.html. Search for DESIGN TOKENS to jump straight to it. You will see a block that looks like this:

:root {
  --bg:          #080808;   /* Page background — near-black */
  --surface:     #111111;   /* Card background */
  --surface-2:   #161616;   /* Hovered / open card background */
  --border:      rgba(255,255,255,0.06); /* Subtle dividers */
  --border-mid:  rgba(255,255,255,0.1);  /* Slightly stronger borders */

  --text-1: #f0ece4;   /* Primary text — warm white */
  --text-2: #8a8580;   /* Secondary text — mid gray */
  --text-3: #504e4b;   /* Tertiary text — dark gray, labels */

  --gold:     #d4ad65;              /* Accent color — warm gold */
  --gold-dim: rgba(212,173,101,0.10); /* Faint gold for button backgrounds */

  --ff-display: 'Cormorant Garamond', Georgia, serif; /* Headings */
  --ff-body:    'DM Sans', -apple-system, sans-serif;  /* Body text */
  --ff-mono:    'Space Mono', monospace;              /* Labels, tags */
}

Changing the accent (gold) color

Find --gold: #d4ad65; and replace #d4ad65 with your new color hex code. Then update --gold-dim to be the same color at low opacity.

Example — to change to a cool blue accent:

--gold:     #5b9bd5;
--gold-dim: rgba(91,155,213,0.10);

Changing the background color

Find --bg: #080808; and change the hex value. The page background, all cards, and borders all adapt automatically because they reference this variable.

Changing fonts

The fonts are loaded from Google Fonts. To use a different heading font:

1

Go to fonts.google.com and pick a font

Click "Get font" then "Get embed code". Copy the <link> tag.

2

Replace the Google Fonts link in index.html

Search for fonts.googleapis.com/css2?family=Cormorant and replace the entire <link href="..."> line with your new one.

3

Update the CSS variable

Find --ff-display: 'Cormorant Garamond' and replace Cormorant Garamond with the exact name of your new font.

How to Deploy (Push to Live Site)

After making any changes to your files, you need to push them to GitHub to update the live site. This takes three commands. Run them in Git Bash or Windows Terminal, inside your project folder.

Opening a terminal in your project folder

Open File Explorer, navigate to the Engineering Site folder on your Desktop, then right-click in an empty area and select "Open Git Bash here" (or "Open in Terminal" on Windows 11).

The three deploy commands

Run these in order. Copy each line exactly:

# Step 1 — Stage all your changed files
git add .

# Step 2 — Save a snapshot with a description of what changed
# Replace the message in quotes with your own description
git commit -m "Update about section text"

# Step 3 — Send to GitHub (this updates the live site)
git push origin main

After Step 3, wait 1–2 minutes, then refresh your live URL to see the changes.

What if git push asks for a username and password?

GitHub no longer accepts passwords. You need a Personal Access Token:

1

Go to github.com → Settings → Developer Settings → Personal Access Tokens → Tokens (classic)

2

Click Generate new token. Give it a name. Check the repo scope. Set expiry to 1 year. Click Generate.

3

Copy the token. When git asks for your password, paste the token instead. Your system will remember it.

Useful extra commands

CommandWhat it does
git statusShows which files have been changed but not yet committed
git log --onelineShows your recent commits as a short list
git diffShows exactly what text changed in your files

How to Add New Pages

GitHub Pages serves any index.html found inside a subfolder as a page at that folder's URL. So to add a new page, you just create a new folder with an index.html inside it.

Example: adding a blog page at /blog/

1

Create the folder

Inside Engineering Site, create a new folder called blog.

2

Create an index.html inside it

Create a file called index.html inside the blog folder. This can be any HTML page you like.

3

Link to it from the main portfolio

In index.html, add a link like: <a href="/blog/">Blog</a>

4

Deploy

Run the three deploy commands. Your new page will be live at https://eddywin-bit.github.io/engineering-portfolio/blog/

Linking back to the portfolio from a subpage

Inside any subpage's HTML, use this to link back to the main portfolio:

<a href="/">Back to Portfolio</a>
<!-- or, using the full path: -->
<a href="/engineering-portfolio/">Back to Portfolio</a>

Paths on GitHub Pages

Because your site lives at /engineering-portfolio/ (not the root domain), absolute paths like /images/photo.jpg will break. Always use relative paths from within subpages, e.g. ../images/photo.jpg to go up one level, or link from the root using the full subfolder path.

Troubleshooting

Problem Likely cause Fix
Live site not updating after push GitHub Pages takes 1–2 minutes to rebuild Wait 2 minutes and hard-refresh (Ctrl+Shift+R). Also check the Actions tab on GitHub for build errors.
Site shows a 404 error GitHub Pages not enabled, or index.html not at root Go to repo → Settings → Pages → set Source to Deploy from a branch, branch = main, folder = / (root).
Resume button opens a blank page or 404 PDF filename doesn't match the link in index.html Confirm the PDF file is named exactly Edwin_Gyasi_Resume.pdf and is in the root folder. Check for typos — capitalisation matters.
Accordion (case study) not expanding JavaScript error in the page Open the browser, press F12, click the Console tab. Look for any red error message and note what it says.
Fonts not loading (showing Times New Roman) No internet connection, or Google Fonts blocked The site requires an internet connection to load fonts from Google. This only affects offline viewing.
git push fails with "rejected" Remote has changes you don't have locally Run git pull origin main first, then push again.
git push asks for password and fails Password auth is disabled on GitHub Use a Personal Access Token as your password. See Section 06 for instructions.
Page looks broken on mobile You edited CSS and broke a responsive rule Restore from your backup copy of index.html. The responsive rules live near the bottom of the CSS, under @media (max-width: 960px).
Images in designs/ not showing on live site Filename case mismatch (Windows is case-insensitive, GitHub is not) Make sure filenames and their references in the HTML match exactly — including capitalisation. Photo.jpg ≠ photo.jpg on GitHub.
Accidentally deleted something — Run git checkout HEAD index.html to restore the last committed version of index.html. This undoes any unsaved edits.

How to undo the last deploy

If you pushed a broken change and want to roll back to the previous version:

# See your recent commits — note the ID of the one you want to go back to
git log --oneline

# Revert the most recent commit (creates a new "undo" commit)
git revert HEAD

# Push the revert to update the live site
git push origin main

Key design principles to follow

  • Gold is used sparingly. It appears on: the hero label, the small "Available" dot, project numbers, toggle buttons, card left-bars on hover, and skill chip hover states. Do not use gold for large areas of text or backgrounds.
  • Use italic Cormorant Garamond for contrast. Section headings use the italic form (in a lighter gray) to create rhythm alongside the regular weight. E.g. "About / Me".
  • Everything fades in on scroll. Any new content block you add should include class="reveal" so it animates in. Add d1 through d6 for staggered delays.
  • Monospace font stays small. Space Mono is always used at 9–11px, all-caps, with generous letter-spacing. Never use it for body text.
  • Negative space is intentional. The generous padding between sections is a design choice — resist the urge to fill empty space with extra elements.
